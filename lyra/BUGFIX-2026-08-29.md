# Lyra Bug Fix - 2026-08-29

## Problem

When users tried to run commands with arguments like `cd docs`, Lyra would incorrectly parse the argument as a separate command, resulting in the error:

```
Error: Undefined command: docs
```

## Root Cause

In the parser's `parse_call()` method, when parsing command arguments, it was calling `parse_primary()`. However, `parse_primary()` treats any identifier (`Token::Ident`) as a potential command name and recursively calls `parse_call()`. This caused arguments like "docs" to be interpreted as command invocations rather than string arguments.

**Example of the problem:**
- Input: `cd docs`
- Lexer output: `[Token::Ident("cd"), Token::Ident("docs")]`
- Parser behavior:
  1. Recognizes "cd" as a command
  2. Tries to parse "docs" as an argument
  3. Calls `parse_primary()` which sees `Token::Ident`
  4. `parse_primary()` calls `parse_call()` for "docs"
  5. Results in error: "Undefined command: docs"

## Solution

Created a new `parse_arg()` method specifically for parsing command arguments. This method:

1. **Treats identifiers as string literals** instead of command calls
2. **Supports path parsing** by combining consecutive path-related tokens (`/`, `.`, `-`, identifiers, numbers)
3. **Maintains support** for other argument types (strings, numbers, variables, lists, records)

### Changes Made

**File: `lyra/src/parser/mod.rs`**

- Modified `parse_call()` to use `parse_arg()` instead of `parse_primary()` when parsing command arguments
- Added new `parse_arg()` method with path-aware parsing

### Path Parsing

The new implementation intelligently combines tokens to form paths:

```
Input: cd /home/user/projects
Tokens: [cd, /, home, /, user, /, projects]
Result: Call { name: "cd", args: ["/home/user/projects"] }
```

```
Input: cd docs
Tokens: [cd, docs]
Result: Call { name: "cd", args: ["docs"] }
```

## Test Coverage

Added integration tests in `lyra/tests/test_cd_command.rs`:

- `test_cd_with_argument` - Tests simple directory names like "docs"
- `test_cd_with_path` - Tests absolute paths like "/home/user/projects"
- `test_ls_with_argument` - Tests other commands with arguments

All existing tests continue to pass (25 unit tests + 3 new integration tests).

## Examples of Fixed Behavior

### Before the fix:
```bash
λ ~/Projects/SOL (main) 〉cd docs
Error: Undefined command: docs
```

### After the fix:
```bash
λ ~/Projects/SOL (main) 〉cd docs
λ ~/Projects/SOL/docs (main) 〉pwd
/home/user/Projects/SOL/docs
```

### Also works with paths:
```bash
λ ~ 〉cd /home/user/Projects
λ ~/Projects 〉pwd
/home/user/Projects
```

### And other commands:
```bash
λ ~ 〉ls docs
README.md
architecture.md
...
```

## Impact

This fix resolves a critical usability issue that made basic shell commands unusable. Users can now:

- Change directories: `cd docs`, `cd /path/to/dir`, `cd ..`
- List specific directories: `ls src`, `ls /home`
- Run any command with file/path arguments
- Use relative and absolute paths
- Use paths with numbers, dots, and hyphens

## Notes

This is a parser-level fix that doesn't change the evaluator or built-in command implementations. All commands that accept file paths or directory names will benefit from this fix automatically.
